# 员工端与 DSH 对齐记录（2026-11-24）

本记录说明员工桌面端（AIbertAI）这次和 DSH SDK 对齐的六项改动，以及 Agent 各项能力与 DSH 的对照。员工端新会话的智能体循环本身就是 DSH SDK，因此对齐的原则是：DSH 有的能力直接复用，宿主只在 DSH 留出的接缝上补企业能力（模型网关、计费、画布、连接器、审计）；不再自建一套与 DSH 平行的规则。

## 本次修复

### 1. 自动压缩阈值：200K 上下文在约 90K 就压缩

DSH 的 `compaction-basic` 触发点为 `floor(min(W × 0.8, W − O − 65536))`，其中 `O` 是路由**配置的**每次请求输出上限。宿主原先把后台的"最大输出"写成模型条目的 `maxTokens`，DSH 把它当成固定预留：200K 窗口、约 45K 输出时触发点是 89,464，即用户看到的约 90K。实际上 pi-ai 适配层已经把每次请求的 `max_tokens` 限制在 `窗口 − 当前提示 − 4096`，固定预留属于重复计算。

现在后台输出上限作为路由的模型能力（`defaultMaxTokens`）下发，pi-ai 仍按剩余空间发送和截断，DSH 不再固定预留。`compaction-basic` 的模型策略为 `thresholdRatio 0.85`，`headroomTokens` 取 15% × W 与"4096 + min(输出上限, 8K)"中的较大值（后者不超过半个窗口），摘要输出上限取输出上限与 32K 的较小值。

用 DSH 自带的 `resolveCompactSpec` 校验：200K、128K、1M 窗口的触发点都是 85%（200K 为 170,000）；32K 和 64K 窗口约为 81%，以便压缩前仍留有回答空间；8K 窗口为 50%。保留区间始终低于触发点。实现见 `native/dshcompactionpolicy.go`。

### 2. 调用失败后会话锁死

DSH 的智能体循环从不因上一轮失败而锁会话：失败记录在会话里，Agent 回到空闲，下一条消息正常进入。恢复时 `core/session/repair` 会给没有结果的工具调用补一条"结果未知：只读或幂等操作可重试，有副作用的先核实外部状态或询问用户"，由模型判断。

宿主原先在 `reserveTurn` 里拦截下一条消息（`dsh_reconciliation_required`，即"上次操作结果尚未核验，暂时无法继续"）。现在发送前会先尝试结算上一轮的模型调用，然后放行下一条消息。只保留一种情况会等待：上一轮本身就是未结算的模型调用，网关日志里仍有 `pending.json`，并且刚才的结算没有成功。这时提示点「重新核验」查询回执。以下保障仍在各自的位置生效：

- 失败轮次的 SDK 子进程会被丢弃。
- 续接前仍会先对账未决的模型调用，失败只影响这一次尝试。
- 有副作用的调用如被重放，仍由其持久化凭据拒绝。
- 失败轮次原样保留在磁盘上，"重新核验"计费回执的入口不变。

失败后切换模型也放宽了：只有网关日志里仍有未结算的模型调用时才拒绝。界面上相关错误提示改为"可以直接继续"，给模型的工具失败原因改为"先读取现状再决定是否重做"。

### 3. 编辑等工具行没有对齐

DSH 为 `edit`、`write`、`apply_patch`、`read`、`grep`、`glob`、`web_search`、`web_fetch`、`bash` 和 Office 工具注册了专用工具行（`ui-tool` 的 `tool.call.toolview`），只有没有专用行的工具才回落到 `GenericToolCard`；员工端原先对所有工具都用通用卡片。`dsh-integration/chat-renderer.tsx` 现在按 DSH 的注册表选择工具行：编辑和写入显示路径、内容大小（如"编辑 a.yml 1KB"），并可展开改动对比，bash 使用 DSH 终端行。成员会话复用同一渲染器。`read_image`、`todo_write`、`ask_user_question` 依赖 DSH 宿主插槽，仍由员工端已有界面承载。

### 4. 文件位置与文件面板

DSH 首次使用时创建一个可见的默认工作区 `~/Documents/deepseek-harness/default-workspace`，所有未选择项目的会话共用它，任务在其中建自己的子文件夹；删除会话不删除文件。员工端原先为每个会话在 `.local-runtime/…/workspaces/<会话ID>` 下建隐藏目录。

现在未选择项目的新会话共用 `~/Documents/AIbertAI/default-workspace`，可用环境变量 `AIBERTAI_DEFAULT_WORKSPACE` 覆盖。该目录按员工选择过的文件夹授权，打开时同样做符号链接校验；无法创建时回落到原来的会话私有目录。删除会话时保留共享目录里的文件。已有会话位置不变。

与 DSH 列出首次使用的工作区一样，这个目录在首次启动时登记为「默认工作区」项目（只登记一次，员工移除后不再加回）。新会话默认归入它，输入框里预选它；此前已在共享目录里的会话也归入它。有了默认工作区后，项目选择里不再提供「不关联项目」。

文件面板的标题栏与 DSH 一样显示工作区路径（过长时从开头省略），右侧为刷新、搜索和打开目录；「工作区文件 / 本次对话改动 / Git 未提交改动」的切换移到标题栏下方。

文件面板按 DSH 默认隐藏以 `.` 开头的条目（如 `.aibertai`、`.ohmyagent`），搜索栏里的眼睛按钮可切换显示；只剩隐藏项时显示"隐藏项未显示"。

对话区右侧接入 DSH 的轮次导航（`TurnNavigator`）：每条员工消息一条刻度，悬停显示该轮提问和回答开头，点击跳到该轮，当前阅读位置的刻度加深。与 DSH 一样，对话区宽度不足约 930px 时隐藏。目前只列出已加载的消息，未加载的更早历史要先向上滚动加载后才出现。

### 5. 权限改为 DSH 的三档

DSH 的权限预设 = 沙箱 + 审批：「仅可查看」为 `read-only`，「工作区内修改」为默认的 `workspace-write`，「完全权限」为 `danger-full-access` + `approval: never`。员工端原先只有「按需确认」和「完全信任」两档，SDK 子进程固定为 `read-only`。

现在员工端使用同样的三档，默认「工作区内修改」。本机交互式、且调用方有写文件权限的会话，新建 SDK 会话时按所选档位使用对应的 DSH 预设；远程中转、后台目标和没有写文件权限的访问者仍固定为 `read-only`，环境变量仍不能覆盖。write/edit 经宿主写入桥时与 DSH 的文件沙箱一致：仅可查看时直接拒绝（模型可带 `sandbox_permissions` 申请升级，由员工确认），工作区内修改时直接写工作区，完全权限时不询问。选择完全权限前与 DSH 一样弹出确认。

DSH 在会话创建时固定预设，SDK 没有中途切换的方法，因此档位在会话发出第一条消息前选定，之后锁定（`session_mode_locked`），审批卡片上也不再提供「完全信任此对话」。旧记录按原来的效果对应：「完全信任」视为完全权限，其余视为工作区内修改。

完全权限下 SDK 不再经过宿主审批，宿主的写文件权限检查、插件管理审批和审计不再拦截这些调用。

### 6. 测试

- Go：`AIbertAI/native` 全量 `go test` 通过。新增 `dshcompactionpolicy_test.go`、`desktopworkspace_shared_test.go`、`dshpermission_test.go`（含待结算模型调用的发送拦截）；`desktopsessions_test.go` 中原先断言"失败后必须锁定"的用例改为断言"可以继续"。
- Web：`tests/dsh_web` 的 node 测试与 `native-reply`、`native-files`、`native-members`、`native-browser` 通过。新增 `native-tool-rows.mjs`，用旧包运行时它会在内容大小断言处失败，说明测试能区分新旧行为。
- 重新生成的 `code/web/dsh/native-chat` 与 `native-files` 已核对：未改源码时重建结果与提交版本一致，仅分块文件名不同。

## Agent 能力对照

| 能力 | DSH | 员工端现状 | 结论 |
| --- | --- | --- | --- |
| ReAct 循环 | `core/agent-loop`：turn → step → 工具批次 → 下一步；`next-step` 收件箱支持中途插话；失败只结束本轮 | 直接运行同一个 SDK 循环 | 已复用；本次去掉了宿主额外的失败锁 |
| 工具调用 | 原生工具 + `tools/execute` 中间件；失败作为 `isError` 结果交给模型 | write/edit 经宿主写入桥（凭据、回执、恢复），画布与连接器经 host-tool | 架构一致；失败原因文案已改为让模型自行判断 |
| 权限与沙箱 | 预设 = 沙箱 + 审批；默认 `workspace-write`，完全权限为 `danger-full-access` + `never` | 原为固定 `read-only` | 改为同样的三档，默认工作区内修改；会话开始后锁定 |
| 上下文与压缩 | `compaction-basic`：压力触发、溢出恢复、`/compact`、工具输出裁剪 | 复用；阈值曾被重复预留拉低 | 已修正为 85% |
| 记忆 | 没有独立的长期记忆插件；靠 `agent-instructions`（AGENTS.md 链）、技能、会话历史检索（`session_search` 等）和压缩摘要 | 复用相同插件；专家提示词作为宿主指令注入 | 与 DSH 一致，无需另建 |
| 任务规划 | `todo_write`；`plan-mode` + `exit_plan_mode` 审阅；`/goal` 持续目标 | 待办面板已接入；Goal 由宿主管理；缺少计划审阅侧栏 | 差距：计划审阅界面 |
| 反思 / 自检 | 没有单独的反思模块；靠工具错误回灌、"结果未知"修复提示、Goal 轮次评估、workflow | 复用 | 一致 |
| 多智能体 | `subagent`、`subagent_fork`、`agent-team` 共享任务板、成员消息 | 已接入，含成员会话与追问 | 一致 |
| MCP | `mcp-client` / `mcp-manager` / `mcp-resources` | 连接器和本机 MCP 由宿主管理（`localmcp.go`），以 host-tool 下发；SDK 仅挂载 `mcp-resources` | 架构不同但等价，便于企业侧统一授权和审计 |
| 定时任务 | `schedule` / `tool-schedule` | 宿主禁用，因为宿主按会话租用 SDK 子进程，无法拥有全局调度文件 | 差距：需接入宿主统一调度 |

## 尚未处理

- **会话中途切换权限：** DSH 把权限预设记录在会话里，SDK JSON-RPC 没有切换预设的方法，因此档位在会话开始后锁定。如需中途切换，要在 SDK 补丁中增加切换预设的 RPC，并在 Mac 上用 `build-dev-sdk.sh` 重新构建 SDK。
- **停止未确认时的残留命令：** 停止未被确认时，宿主会结束 SDK 子进程，但 DSH 在独立进程组里启动的 shell 命令可能继续运行。原来的会话锁会挡住下一条消息，现在不再阻挡。可以考虑在丢弃子进程时一并结束其进程组。
- **连接器调用：** 结果未知的连接器调用不会以同一调用 ID 重放，但模型可能换一个新调用重做。是否重做由模型按提示（"先核实远端或询问用户"）决定，与 DSH 的恢复语义一致。
- **共享默认工作区：** 与 DSH 一样按系统用户共享，同一系统用户下的不同员工账号会看到同一个文件夹。目录若被替换为指向别处的符号链接，不会自动重新授权，新会话会回落到私有目录。
- **已有竞态：** 旧网关实例的请求处理程序可能在新实例归档 `pending.json` 后再次写入。这是原有问题，但取消会话锁后下一轮开始得更早，这个时间窗口变大了。
- **计划审阅侧栏**（`exit_plan_mode` 的提交、批准、重开）尚未接入。
- **通用定时任务**尚未接入宿主统一调度。
- 员工工作台主程序只有构建产物（`code/web/assets/index-*.js`），本次只修改了其中的提示文案。涉及交互的改动需要找到其源码后再做。
