# AIbertAI 私有部署验收包

验收程序使用 `AIbertAI/native` 的 Go 源码执行 OAuth PKCE 登录、设备证明、指定模型流式回复及会话上报。它会临时申请一个模型调用密钥，并在验收结束时撤销密钥与授权。会话上报包含状态和 Token 用量，提示词和回复正文留在客户端与模型调用链路。

该程序独立于员工端，用于验证私有部署的文字对话。工具、知识库、文件、历史数据和远程会话使用下文的员工端构建验收。

## 构建

运行 `build-private-acceptance.sh`，按顺序传入 `mac-arm64` 或 `win-x64`、私有后端 origin、后台模型 UUID、模型显示名、输出目录。模型需在后台启用并授权给验收账号，支持 OpenAI Responses 或 Chat Completions。私有后端需启用设备证明与会话上报。

macOS 构建使用本机的 Electron ARM64 和系统 DMG 工具，生成带临时签名的验收包。Windows 构建额外传入 Electron 官方 Windows x64 ZIP，脚本会读取同目录的官方 `SHASUMS256.txt` 并校验；生成的便携包解压后运行 `AIbertAI Runtime Acceptance.exe`。

构建这个独立验收程序时，私有后端 origin 应与 OAuth issuer 一致，并可从验收机器访问。回环地址只适用于与后端同机运行。员工端安装包在登录时填写后端地址，见下文。

## 远程会话宿主的源码验收

原生二进制支持 `verify-remote-runtime PROFILE SESSION_ID APPROVED_FILE`。使用独立测试后端、测试账号、绝对路径的会话副本和指定文本文件。程序输出 OAuth 授权链接，授权后创建临时远程设备，通过既有中转票据读取给定会话，并用 `tools/call` 执行 `read_text_file`。它校对历史记录和工具输出，并验证该工具拒绝读取未授权的路径。验收结束会关闭设备通道并撤销本次 OAuth 授权。

构建时指定 Chat Completions 或 Responses 模型 UUID 后，程序会通过中转 ACP 创建会话，在批准后执行文件读取工具。重连后会重放同一请求，核对已完成的回合没有再次执行，再在同一会话发起第二轮。第三轮会拒绝工具调用，并核对拒绝后没有工具输出。各轮分别上报用量、工具结果及权限计数。工具会把指定测试文件的内容发送给模型，因此请使用合成测试文件。调用密钥会在验收结束时撤销。

同一会话还会经真实中转分块上传一份合成附件，断开 ACP 后读取已写入偏移并续传。验收核对摘要、完成操作查询、签名下载、HEAD、Range 和错路径拒绝。上传暂存只用于本次验收进程。

要在独立员工端联调，把命令改为 `preview-remote-runtime PROFILE SESSION_ID APPROVED_FILE`。完成受限 OAuth 授权后，宿主会临时发布名为「AIbertAI 源码远程验收设备」的设备。通过隔离员工端选择该设备，打开历史副本，或新建会话并发送文本附件。预览最多运行十分钟，也可以中断进程提前关闭。模型目录仅显示构建时指定的模型，附件正文读取仅支持有限大小的 UTF-8 文本。

该入口覆盖已结束的单页历史、重连后的续谈、指定文本文件工具和附件传输。

## 员工端本机开发

在 macOS 运行 `bash AIbertAI/启动员工端.command --dev`，用本地 Electron 启动源码员工端。脚本从 Go 源码构建员工端运行时和浏览器助手。开发版使用独立的 `AIbertAI Dev` 资料目录，也可通过 `AIBERTAI_USER_DATA` 指定测试目录。登录时填写私有后端地址，授权加密保存在当前账号资料目录。后续重启复用同一设备身份。需要验收合成文件时可设置 `AIBERTAI_SOURCE_WORKSPACE_FILE`。

启动时，私有后端若拒绝刷新已失效的授权，员工端会重新打开该后端的浏览器授权页。原账号完成确认后，宿主保存新凭据并恢复启动。

预览使用本机回环 ACP。已有历史只读，最多列出目录中的前一千个条目。长会话默认打开最后一页，本机和远程都可向前或向后翻页，已记录的附件和工具输出可从对应会话读取。默认工作区保存在账号资料目录，迁移前的源码会话保留会话 ID。通过系统目录选择器选中的文件夹可以作为项目工作区。已有 `projects.json` 的项目 ID 和路径会导入新存储，原文件保留用于回滚。工作区支持目录浏览、文件链接和文本预览，模型读写 UTF-8 文件需要逐次审批。新对话按账号和设备落盘，中断回合在重启时补传。上报可在测试后台按会话查看各轮 Token 用量、工具次数和审批结果。

员工端每次可发送四份附件，原件合计最多 32 MiB，发送后可从会话原样另存。UTF-8、DOCX、XLSX 和 PPTX 的正文由宿主提取。单份不超过 10 MiB 的 PDF、PNG 和 JPEG 交给私有后端。PDF 先由后端提取正文，扫描页和图片使用后台配置的文档视觉模型。每轮提交给对话模型的附件正文合计最多 128 KiB，提取失败时仍可下载原件。会话统计上报不包含附件正文。

同一轮可以执行最多四次连续工作区工具调用。每次审批后再执行，结果按顺序显示并写入会话历史。后台会话详情记录工具调用次数，「AI 行为」按内置工具的资源 ID 汇总。

工作区工具支持旧名称 `Read`、`Write`、`Edit`、`Glob`、`Grep`，以及 `list_directory`。会话内可启停这些工具。调用会展示参数，由当前操作方审批。绝对路径须在已授权工作区内，搜索不跟随符号链接。编辑支持同文件批量精确替换，校验全部匹配后再写入。文本预览、搜索和写入受运行时的单次传输大小限制。

`apply_patch` 支持一个补丁新增、更新、移动和删除多个文件。审批前检查所有目标和上下文，提交前再次核对版本。中断提交时，重启读取本地事务记录并回滚未提交的修改。原文件随后有独立改动时，恢复保留该改动并报告冲突。

新运行时按回合存储已确认记录，当前回合和提交位置写入会话清单。首次续写旧版源码会话时保留原快照，会话 ID、工作区和操作 ID 随历史迁移。复制账号资料用于备份时包含整个 `source-runtime` 目录，旧运行时可读取升级前快照。传给模型的历史按模型上下文预算选择最近的完整回合，会话历史仍可逐页查看。

后台暂时拒收时，已完成的回答和工具结果保存在本地。运行时启动后以及运行期间会重试待确认的上报，补传复用同一设备、会话和回合标识。

私有后端发布的连接器从账号目录加载。连接器默认选择按账号保存，单个会话可以调整连接器、工具和凭据。模型调用已选连接器时，员工端展示工具及其参数，批准后经本部署的 MCP 网关执行。网关继续校验资源授权并记录调用，会话上报关联连接器 ID。

开发版员工端和私有后端都更新后，源码运行时启动时会检查当前登录账号的数据目录。它读取 `runtime/ohmyagent` 下索引标记为本机个人资源的专家及连接器，也支持账号目录内的 `mcp.json` 明文导出。加密的本机索引用当前账号的资料密钥读取，原存档继续保留。专家的提示词、规则正文、`SKILL.md` 说明和关联连接器随个人资源导入。远程连接器支持私有后端可访问的 Streamable HTTP 和旧 SSE 地址。旧 SSE 的消息提交地址必须与配置的连接地址同源。旧文件和历史会话保留在原处。

导入成功后在源码运行时的数据目录保存完成记录。重试复用私有后端的导入标识，保留后端已有记录及其后续编辑。HTTP 认证 Header 会作为个人凭证保存并绑定。本机命令、参数和环境变量保存在当前账号的新运行时加密存储中，每轮启动前在桌面端请求确认，调用工具时沿用现有审批。旧专家的工作区工具依赖复用新运行时已有能力。声明画布工具的专家使用自己的会话画布和现有设计服务，包括分镜生产、隔离截图及 PPTX 清单生成。历史媒体任务保留原记录，旧网关任务暂无法续跑。无法打开的存档和缺少兼容实现的宿主工具会列在 `legacyResourceImport.pending`，原始资料继续保留。

在「设置 → 设备」开启远程访问后，员工端通过私有后端发布本机，自身会话与远程会话共用同一份存储。首次申请设备发布和撤销权限时需要正常登录授权。宿主重启后保留设置和设备身份，关闭访问会断开隧道并同步撤销。远程附件完成写入后保存在当前账号的设备目录，下载时使用当前有效的访问票据。旧默认工作区中有历史记录的附件可以从本机和授权的远程会话下载。

会话工具栏的「终端」在宿主的会话工作区内打开交互式 Shell。macOS 使用系统伪终端，Windows 构建使用 ConPTY。远程终端通过私有后端中转，只接受带会话控制权限的连接。客户端窗口关闭后可重新附加同一终端，并在保留的输出范围内补收内容。关闭远程访问会结束由远程连接创建的终端。终端输出和输入控制状态保存在运行时内存中。

用于包内联调时，在应用资源目录加入 `employee-source.json`，指定 `version: 1`。源码运行时放入 `bin/aibertai-native` 或 `bin/aibertai-native.exe`。包内可选的合成工具文件名为 `employee-acceptance.txt`。员工端从内置页面启动该二进制。

安装包启动时校验包内运行时文件。客户登录时输入自己的后端地址，应用按账号保存并使用它。安装包无需为每个部署重新构建。运行时从该后端的授权目录选择第一个兼容文本模型。应用的集成允许正常访问第三方服务。打包脚本检查发包内容是否残留旧网关地址。

使用 `build-employee-candidate.sh` 生成包含真实员工端界面的候选包。依次传入平台、合成文本文件或 `-`，以及输出目录。传入 `-` 时测试实际工作区。Windows 还需提供官方 Electron Windows x64 ZIP 及同目录的 `SHASUMS256.txt`。脚本输出 macOS DMG 或 Windows x64 便携 ZIP，以及 SHA-256 校验文件。回环后端地址适合在运行后端的同一台机器上验收。

## 员工端发行构建

在上述命令的平台参数前加 `--release`，将合成文件参数设为 `-`。macOS 使用固定的应用标识 `com.aibertai.desktop` 和一组对应的 Electron 助手标识。构建机需有官方 `@electron/osx-sign` 提供的 `electron-osx-sign` 命令，以及可用的 Developer ID Application 签名身份。在 `AIBERTAI_MAC_SIGN_IDENTITY` 中指定该身份在本机钥匙串中的名称。脚本启用 Hardened Runtime，校验应用签名，并以同一身份签署含「应用程序」快捷入口的 `AIbertAI-mac-arm64.dmg`。在同一签名身份下完成退出重开、覆盖升级和旧资料读取验收。

对外分发需由获授权的发布人员提交 [Apple 公证](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution)，将公证票据附加到 DMG，重新生成 SHA-256 校验文件，再发送最终包。

Windows 生成带 `AIbertAI.exe` 的 `AIbertAI-win-x64.zip` 便携包和校验文件。当前该构建不做 Windows Authenticode 签名。登录时填写该设备能访问且与 OAuth 发行者一致的后端地址。

员工端随包提供 AIbertAI 浏览器助手。打开「设置 → 浏览器」启用连接，按引导在 Chrome 或 Edge 的扩展管理页加载已解压的扩展。点击扩展图标连接桌面端，再主动分享当前网页。客户端设置页可以读取该页可见正文或定位标签页。页面跳转、关闭或用户撤回分享后，需要重新分享。浏览器助手的连接和正文均在本机处理。

新建会话时可从角色菜单选择「设计专家」，也可通过网页、演示文稿、海报、Logo 或视频入口进入。设计专家的工作规则随源码运行时一起打包，按设计工作区和作品类型加载。它能读取当前画布与选中节点，使用已经落到当前工作区的风格和设计系统。画布操作沿用现有审批。图片、视频生成及导出以当前客户端和后端可用的工具为准。

macOS 覆盖安装后，如已有独立数据文件夹，先退出另一份客户端，再从「设置 → 存储 → 选择已有数据文件夹」选中原目录。员工端验证原目录和加密密钥可读后重启，继续在原路径读取资料及历史附件。切换前的数据目录也会保留，可从同一入口切回。系统要求钥匙串授权时，应用会等待读取结果。授权失败时仍使用原数据位置。

源码员工端的 `AIBERTAI_UPDATE_URL` 可指向私有后端同源的更新目录。更新元数据和下载使用独立的 Electron 网络会话，跨源直连和重定向都会被拒绝。

## 离线视频编辑资源

首次构建前运行 `python3 AIbertAI/packaging/stage-video-codecs.py --download` 准备固定版本的 FFmpeg.wasm。离线构建可提供官方两个 `0.12.9` npm 压缩包，运行同一脚本并传入 `--archives 目录`。脚本核对压缩包及单个文件的 SHA-256。安装包携带两套 FFmpeg 核心、编辑器字体和随附授权文件，编辑器从本地页面资源读取。

## 源码员工端的 Office 预览

源码员工端使用本机回环服务和随包分发的 PDF.js 打开 PDF 与转换后的 PPTX、DOCX、XLSX。macOS 的 Office 转换使用 `/Applications/LibreOffice.app/Contents/MacOS/soffice`，也可在部署环境设置 `AIBERTAI_OFFICE_CONVERTER` 指向绝对路径。转换器使用临时工作目录和用户资料目录，在禁网沙箱中运行，无法读取用户的文档、桌面、下载和凭据目录。文档的宏、外部关联和未受支持的嵌入对象会在转换前被拒绝。缺少转换器时，可编辑导出文件仍保留在工作区，应用会标明排版校验未完成。

转换器从 macOS 系统字体目录加载字体，中文图表标签可回退到黑体。字体配置和缓存随单次转换创建和清理。

PDF.js 使用 npm 的 `pdfjs-dist@5.4.624`，来源压缩包完整性为 `sha512-sm6TxKTtWv1Oh6n3C6J6a8odejb5uO4A4zo/2dgkHuC0iu8ZMAXOezEODkVaoVp8nX1Xzr+0WxFJJmUr45hQzg==`。客户端从包内 `web/office-preview` 加载模块及 worker，许可证与模块一并分发。Windows 的 Office 转换沙箱及实机验收仍待完成。

## 源码员工端的可编辑图表

在幻灯片的图表预览元素上设置 `data-ppt-chart-spec`。例如，带尺寸的预览元素可以携带以下 JSON。导出时保留对应的图表和嵌入工作簿，分类顺序和数值来自这份 JSON。

```json
{"type":"column","categories":["一月","二月"],"series":[{"name":"销量","values":[14,23]}]}
```

支持 `column`、`bar`、`line`、`area`、`pie`、`doughnut`。可提供 `title`、`colors`、`showLegend`、`showValue`、`valueFormat`。在源码 Office 预览中，PPTX 所带的 XLSX 图表工作簿须通过与普通 XLSX 相同的安全检查。其他嵌入对象仍会被拒绝。
